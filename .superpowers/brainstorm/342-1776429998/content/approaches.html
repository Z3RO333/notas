Como estruturar o conteúdo por perfil?

A página /admin/graficos já existe. Escolha como adaptar o comportamento para gestor vs. admin.

A

Renderização condicional por role Recomendado

A mesma URL renderiza conteúdo completamente diferente dependendo do user_role. Gestor vê o consolidado existente + novos KPIs de tempo/conversão. Admin vê somente a sua visão pessoal filtrada.

Prós

  • Sem tabs — cada perfil vê exatamente o que é dele
  • URL limpa, sem parâmetros
  • Fácil de manter separado no código

Contras

  • Se um gestor quiser simular a visão de um admin, não consegue
B

Tabs por perfil na mesma página

Uma aba "Visão Geral" (sempre visível para gestores) e uma aba "Minha Visão" (visível para todos, mas filtra pelo próprio admin). Gestores podem trocar entre as duas.

Prós

  • Gestor pode comparar visão geral com visão individual
  • Navegação explícita

Contras

  • Admins enxergam uma aba vazia ou bloqueada
  • Layout mais pesado para um uso que é raro (gestor simulando admin)
C

Seção unificada com KPIs contextuais no topo

A página tem sempre a mesma estrutura: KPIs no topo + detalhamentos abaixo. Para gestores, os KPIs são do consolidado geral. Para admins, os mesmos KPIs mas com dados da carteira. O restante da página (por loja, por colaborador) se adapta silenciosamente.

Prós

  • UX consistente — estrutura idêntica para todos
  • Não precisa de tabs nem lógica de visibilidade

Contras

  • A diferença de escopo (geral vs. pessoal) pode não ser óbvia para o usuário
  • Exige label claro indicando o escopo ativo
